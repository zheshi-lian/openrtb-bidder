OpenRTB 接入文档

本文档对应线上 https://dellai.xyz 的真实接口。所有示例可直接 curl 运行，返回结构与线上完全一致。

① 开发者 · 变现（SSP） ② 广告主 · 投放（DSP / 广告交易引擎） ③ Prebid.js 接入 ④ 结算与对账 ⑤ 信任层 ads.txt ⑥ eCPM' 公式 ⑦ 品类枚举与归因对接

① 开发者 · 变现（SSP）

媒体方取 api_key（见 自助开户），页面贴入广告位 SDK。SDK 自动调用 /openrtb2/bid 出价、渲染胜出广告、上报曝光/点击/VAST 事件。

curl -s https://dellai.xyz/api/publisher -X POST -H "Content-Type: application/json" \
  -d '{"domain":"mygame.example.com","name":"MyGame","contact":"you@mygame.com","site_url":"https://mygame.example.com"}'
# → {"api_key":"pub_…","payout_rate":0.7,"snippet":"
"}

合规爬取会读取你填的 site_url（仅爬你自己声明的页面）补全品类/地域/关键词 → 该位库存被意图匹配时 eCPM 更高。同一媒体 24h 冷却一次。

② 广告主 · 投放（DSP / 广告交易引擎 出价）

向 /openrtb2/bid 发 OpenRTB 2.6 请求。未通过审核或预算不足的请求返回 nbr，合法请求保证有应答、不空跑库存。

curl -s https://dellai.xyz/openrtb2/bid -X POST -H "Content-Type: application/json" \
  -d '{"id":"r1","imp":[{"id":"i1","banner":{"w":300,"h":250},"bidfloor":0.5}],"site":{"domain":"dellai.xyz"},"device":{"ua":"M","ip":"0.0.0.0"},"at":2,"tmax":2000}'
# → {"id":"r1","seatbid":[{"seat":"zhuque","bid":[{"id":"bid1","impid":"i1","price":…,"adm":"…","crid":"…","cid":"…",
#     "ext":{"intent_score":…,"intent_source":"llm|heuristic|embedding","bid_basis":"CPM|CPA|ROAS","shade":…,"pWin":…}}]}]}
# 无匹配：{"id":"r1","seatbid":[],"nbr":2}   nbr=8 容量节流 / 3 未过审

作为外部 DSP，把你自己的 OpenRTB 端点注册进来（DSP 接入）：POST /api/dsp/register，平台会在每次拍卖中并发调用你的 bidder_url。

③ Prebid.js 接入（前端竞价）

端到端示例见 Prebid 演示页。最小可用配置：

pbjs.addBidder('applink', {
  params: { url: 'https://dellai.xyz/openrtb2/bid', imp: { banner: { w: 300, h: 250 }, floor: 1.0 } }
});
// 服务端按 OpenRTB 2.6 返回 seatbid；Prebid 渲染胜出广告并回调 onBidWon
// 设备指纹 device.fp 用于跨 App 归因与风控；浏览器示例仅做展示，不触发真实扣费

④ 结算与对账

账户余额由管理员在核实到账后入账。广告主扣账仅接受平台服务器生成的 HMAC 签名成交回调；成交回调端点为 /notify（等价别名 /api/notify，两者同一套 HMAC 校验与去重逻辑），不接受浏览器或客户手工请求，签名不符返回 401 invalid_notify_signature；余额与计划预算须同时足额才扣账。去重身份 = (impid, reqid)，重复回调返回 {"ok":true,"dup":true} 不二次扣费。

当前公开 Prebid 页面只验证报价与渲染，不做真实扣费。小规模托管试投请使用已审核计划，通过平台 SSP 服务端竞价路径结算；外部 DSP/浏览器直连的真实扣账暂不开放。

报表用途鉴权
/api/reports/publisher媒体收益（清盘价、分成、应结、广告单元拆解）媒体账号令牌 · X-Api-Key · 管理员令牌（管理员须带 domain 或 api_key 参数）
/api/report/advertiser广告主聚合（曝光/花费/GMV）管理员
/api/reports/settlement平台毛利（Σ清盘价 − Σ分成）管理员（需 reports:settlement）
/api/reports/reconciliation双端对账差异（区分 AMOUNT_MISMATCH 与 ORPHAN_LEDGER）管理员（需 reconciliation:read）
/api/demo/report免登录只读快照（演示页用）

⑥ eCPM' 公式

eCPM' = 效果预测 × LTV × 折算出价 × 服务承诺。效果预测 = α·评测分 + (1−α)·行为数据，α = N0/(N0+n)，N0=20（冷启动先验随归因样本衰减）。统一折算到"每千次曝光"口径排序，避免"出价高但效果差"抢量。

CPM：unified = bid / 1000
CPC：unified = bid × CTR
CPA：unified = bid × CTR × 商机率
ecpmPrime = pEffect × ltvFactor × unified × svcFactor

免费试算：eCPM' 打分器。同一引擎跑在生产 /openrtb2/bid 里。

⑦ 最小可跑通样例（粘贴即填充）

从「粘贴代码」到「看到填充」的端到端可复制步骤。假设你的媒体域名是 mygame.example.com，已在 自助开户 拿到 api_key 并创建了广告单元 au_demo_001。

  1. 在页面放一个广告位容器，并引入 SDK（SDK 会自动向 /openrtb2/bid 竞价、渲染胜出广告、上报曝光/点击）：
<div class="ad-slot" data-ad-unit="au_demo_001" data-format="rewarded" data-floor="1.0"></div>
<script src="https://dellai.xyz/pub_sdk.js"></script>
  1. 打开 集成自检 点「运行自检」即可看到「收到请求 / 有胜出」；点「加载一支测试广告」还能主动触发填充。
  2. 想立刻看效果，去 Prebid 演示页 点「重新竞价」——有需求返回真实广告，无需求返回保底测试广告。

进阶：原生 App 见 原生 SDK 接入（iOS / Android）；密钥/收款/结算见 账户与结算。

⑦ 品类枚举与归因对接

竞价侧按计划的 app_category 与竞价请求的 imp.ext.cat 做精确等同匹配：二者不一致的计划不会参拍（nbr=2）。请保证二者在同一枚举内取值。

计划品类（建计划表单 / 账户品类）枚举：
  tools（工具）· puzzle（益智）· casual（休闲）· game（游戏）· social（社交）· ecommerce（电商）· finance（金融）
演示竞价请求（media-demo.html / index.html）统一使用 cat=game；
因此新建计划保持默认 game 即可直连命中，也可改用上述任一值并让媒体侧 cat 与之相同。

第三方归因（MMP）：平台已内置 AppsFlyer / Adjust / Singular / Kochava / Tenjin / Branch 对接。广告主可在后台「归因/追踪」页配置回传地址（postback_url）与归因窗口/去重规则，并获取点击/曝光监测链接模板与 macro（{impid} {clickid} {cid} {publisher}）。S2S 转化回传入账端点：POST/GET /api/track/mmp-postback?impid={impid}。
