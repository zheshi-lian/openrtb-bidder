核心能力架构 · 6 项 CAP

流量侧与需求侧在交易所内实时撮合，所有结果回流到数据飞轮。以下每一项均非 PPT，可在演示中实际运行。

CAP 01

双向 OpenRTB 实时竞价 · 进程内核

自有 DSP 进程内参拍（无自回环 HTTP）+ campaign 内存快照 & 倒排索引（热路径零 DB，微秒级取候选）+ SSP 多需求方二价清算（second-price），媒体分成透明、可审计。

CAP 02

全链路归因与增量度量

多触点归因、SKAN 视图归因，holdout / ghost ads / geo-lift 增量实验——用数据证明广告「真的有效」，而非自报转化率。

CAP 03

创意自动化工厂

可玩广告、DCO 元素级组合、文生图 / 图生视频、多语言本地化——批量派生多形态素材，零生成成本、秒级产出。

CAP 04

ESMM 多目标预估 + 智能出价

多特征 LR 实时打分（相关性）+ 可插拔双塔向量通道 + CTR/CVR 多任务（pCTCVR = pCTR·pCVR 规避样本选择偏差）+ pLTV 多目标 + bid shading + eCPM′ 贝叶斯冷启动。

CAP 05

增长 Agent + 数据飞轮

读懂 Brief → 生成创意 → 真实建 campaign 参拍 → 读实测 eCPM/eCPA → 回流重训模型，闭环自进化（领先于竞品的智能体编排层）。

CAP 06

合规与品牌安全基线

IAB/GARM 品牌安全、post-ATT 设备身份图谱、ads.txt / app-ads.txt / sellers.json 校验。

第一性原理：广告平台的本质是「撮合 + 数据飞轮」——模型越准，广告主 ROI 越高，预算越多，数据越厚，模型越准。飞轮一旦转起来，后来者很难追。这是 AppLink 把 AI 引擎当核心资产的原因。

技术架构概览

AppLink 采用模块化微服务架构，各模块可独立部署、独立扩展。

模块技术栈职责
竞价引擎Node.js + Redis + 内存快照OpenRTB 2.6 实时竞价，进程内核零 HTTP 开销
需求侧 DSPNode.js + 多目标预估模型CTR/CVR/pLTV 预估，eCPM' 排序，bid shading
供给侧 SSPNode.js + OpenRTB 适配器多需求方并发询价，二价清算，媒体分成
素材库S3 + CDN + 元数据库多形态素材存储，DCO 元素组合，版本管理
归因引擎Node.js + 事件流多触点归因，SKAN 视图，增量实验
风控系统Redis + 设备指纹库实时黑名单，跨设备重放拦截，GARM 分层
结算账本Node.js + HMAC 签名S2S 回执验证，双端账本，逐笔对账
管理后台React + Node.js API运营控制台，客户管理，审计日志

关键设计决策：竞价热路径跑的是多特征 LR 实时打分（毫秒级响应），LLM 用于慢速冷启动画像，不进热路径以避免 p99 抖动。模型越准 → 广告主 ROI 越高 → 预算越多 → 数据越厚 → 模型越准，形成数据飞轮。
