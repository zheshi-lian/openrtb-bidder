# AppLink 托管试投运行规则

本规则用于小规模、人工托管试投，不代表平台已具备全自动自助投放或在线支付能力。

## 资金规则

1. 广告主线下付款，运营核实银行到账后，由管理员通过 `POST /api/advertiser/recharge` 入账。
2. 广告主角色调用充值接口必须得到 `401`；管理员凭据只保存在管理员设备或受控密钥管理处，不发给广告主。
3. `/notify` 只接受平台服务器 HMAC 签名，浏览器和客户侧不能直接伪造扣费。浏览器 Prebid 页仅展示报价和渲染，不是计费证据。
4. 一次成交只有在广告主账户余额和计划预算都足额时才同时扣减；任一不足则不返回广告，记 `insufficient=1` 供运营排查。
5. 媒体应付只在广告主扣费确认后计提。媒体付款仍由运营线下执行并留存付款凭证。

## 试投前检查

- 使用单独的试投广告主、单个已审核计划和明确的 campaign 总预算/日预算；先小额到账再入账。
- 只接入已经人工审核、授权证明齐全的媒体；生产模式不启用内置模拟 DSP。
- 管理员完成一次充值后，核对广告主余额、计划预算、赢价流水、`adv_ledger`、媒体应付和对账报表。
- 点击浏览器演示页不会发生真实扣费；端到端成交必须走平台控制的 `/ssp/bid` 服务端竞价路径。
- 发生 `insufficient=1`、对账差异、重复 imp/req、计费服务 5xx 或供给身份不明时，立即暂停计划，不先扩量。

## 生产配置底线

- 设置 `NODE_ENV=production`、强管理员口令 `ADMIN_PASS`（至少 12 位）、独立的 `ADMIN_TOKEN` 与 `RW_SECRET`（至少 16 位），以及独立数据库账号密码。
- 不设置 `ENABLE_DEMO_ACCOUNTS=1`；生产模式忽略该开关并停用演示广告主/媒体账号。
- 变更上线前备份数据库；不要在生产库运行 `smoke_test.js`、`verify_integration.js` 或会创建/修改计划的演示脚本。
- 用户名密码等凭据一旦曾经公开或被多人共用，先轮换再开始试投。

## 验收口径

- 角色校验：广告主不能加余额；管理员能在核实线下到账后入账。
- 竞价计费：重复同一 `(impid, reqid)` 不重复扣款；金额被篡改的 `/notify` 验签失败。
- 余额保护：低于成交清算价时不返回广告、不计媒体应付，并留下可追查的不足额流水。
- 对账：每笔已扣金额可关联到 campaign、impid、reqid；广告主消费、媒体应付、平台差额可复算。
- 效果：广告主确认的转化事件与媒体/广告主口径一致后，才将该试投标记为效果验证通过。
